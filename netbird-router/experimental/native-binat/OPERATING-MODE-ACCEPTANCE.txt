Operating boundary and the owner-death finding
---------------------------------------------
Candidate path: actual pinned NetBird v0.80.0 Engine + selected small-native
patch + native nft backend + explicit userspace WireGuard + NEW nonpersistent
TUN. RequireFreshUserspaceOverlay runs before newWgIface; RequireEphemeralTUN
checks the actual rtnetlink type/nonpersistent flag. Native ACL compiler is the
only rights authority. Policy readiness is not a second ACL. Metrics stay 100/200.

Unsupported: persistent veth/TUN, kernel WireGuard, existing overlay adoption,
legacy iptables filter state, firewalld, old external ACL copier and research
mark/proof publisher. No automatic migration. PVE LXC/VM needs separate host
TUN/capability acceptance; ARM64/Pi is not this candidate's delivery target.

P1_SMALL_NATIVE_OWNER_DEATH_NEW_FLOW is NOT a stock legacy-copier test. It kills
our native gate TEST DRIVER while persistent veth nb0 and synthetic native ACLs
remain. nft rules do not expire when a netlink writer exits. Old READY and the
synthetic ACCEPT remain; a NEW tuple reaches lp. Thus this is a real process/
dataplane-lifetime security failure for that fixture, not a fabricated pass or
an incorrect nft verdict. It does not run the actual Engine admission/TUN checks.
The test now records owner=false, overlay_kind=veth, overlay_survives=true,
ready_rule_survives and unchanged foreign rules before the original assertion.

The candidate prevents that specific continuing-dataplane model by refusing
persistent interfaces. Actual-client SIGKILL and VM tests separately require
TUN disappearance and denial of NEW traffic. This is relevant whenever the
lifetime restriction is bypassed, regresses, or an interface is adopted. It is
NOT a proof of a new bypass of the admitted nonpersistent-TUN Engine path.
The counterexample remains mandatory and red. No claim of general owner-death
safety, and no waiver/merge approval follows from this classification.

Eight concrete acceptance cases
-------------------------------
Common: fresh isolated real controller and six real patched clients; two equal
192.168.88/24 LANs; distinct virtual /24s; no host networking; synthetic keys.
Each case needs baseline positive traffic, a causal local publication barrier,
negative packets and recovery. API success is NOT local kernel/controller ACK.

A related_icmp — executable: packets.related_error + related.py
  Send ONE UDP parent to LAN recorder 8086; retain actual client socket. Emit
  ICMP destination-unreachable quoting the LAN-observed NAT tuple. Require raw
  client capture matching original virtual destination/source port, and an
  increment in the routers' ct state RELATED observation counters. Withdraw
  membership, await newer local publications, emit the SAME parent's ICMP again:
  counter must increment but client must receive no matching error. No new UDP
  request after withdrawal. Missing parent/RELATED classification is a failed
  proof, never accepted as successful denial. Counters grant no permission.
B concurrent_policy_reset — actual Engine injector still absent, BLOCKED
  Barrier inside actual ACL update after close/before publication. Send map N,
  pause it there, Reset actual firewall/epoch; send newer map N+1 with DROP,
  release N. Continuously inject fresh TCP/UDP and established replies. Require
  no READY from stale completion, denial, then recovery ONLY from current full
  map. Repeat at each publication boundary, foreign rules unchanged. Existing
  Go ResetInvalidatesPendingOpenBeforeIO/race tests are partial evidence only.
C unknown_stale_networkmap — management stream injector absent, BLOCKED
  On a fresh actual Sync stream inject N complete allow; inject N-1, then N+1
  with unknown field/invalid port/incomplete route selectors. Require CLOSED,
  no new or existing scoped packets, no locally applied marker for invalid map.
  Replay valid old N: still CLOSED. Send complete N+2: recover. Existing native
  map validator/rejected-serial Go tests execute but are not daemon proof.
D kernel_ack_failure — targeted actual-daemon netlink injector absent, BLOCKED
  At publication transaction fail ACK with EPERM/ENOENT; independently lose a
  readback reply after a successful write. Require no local-publication event,
  CLOSED, old/new request/reply denial; unconfirmed closure must stop owner and
  remove TUN. Recover with fresh map, same identity. Controller stop, deleting
  a table as an unrelated privileged writer, or replacing callbacks is NOT the
  requested actual ACK-loss test. Core fake-I/O and VM fail-stop are partial.
E icmp_port_protocol_restrictions — executable: extended_policy_cases
  First prove TCP 8082/UDP 8083 services and ping work under all-protocol policy.
  Install separate native one-rule UDP8081 and ICMP policies, acknowledging
  each single mutation on the A primary/backup, then replace the broad A policy with
  TCP8080. Strict GET readback is required for every individual policy. Require exact allowed services,
  ping positive, alternate live services AND crossed UDP8080/TCP8081 services denied.
  Each crossed service must work before restriction and after restoration. Remove ICMP alone, await native
  publication, ping denied while allowed TCP/UDP still work. Restore all; prove
  alternates/ping recover. Service absence cannot masquerade as policy denial.
F multiple_independent_acl_sources — executable: extended_policy_cases
  Keep A source=peer; change B source=probe, with independent destination/router
  groups. Require peer->A yes/B no and probe->A no/B yes through equal real LANs.
  Restore B to peer, await newer B publications and prove both reverse outcomes.
G fresh_map_after_native_firewall_rebuild — live Reset fixture absent, BLOCKED
  Begin valid actual Engine allow. Invoke ITS native firewall Reset without
  restarting process or reenrolling. Keep management full-map response paused.
  Require CLOSED/no new traffic across table removal/recreation. Cached serial
  or handles must NOT reopen. Deliver current complete map, require fresh local
  publication + recovery, same peer ID. Same-identity process restart is tested
  separately and does not replace this live-reset case.
H established_reply_only_tcp_udp — executable: real autonomous LAN streams
  Establish TCP8084 and UDP8085; prove server-originated data arrives. Only the
  initial connect/handshake writes client data. Withdraw group and wait for all
  routers' new local publication; take a monotonic_ns barrier. Query existing
  sockets without any new application request. Reject any server frame SENT
  after that barrier. Frames sent before it cannot prove post-publication
  leakage. No time namespaces: containers/runner share kernel monotonic clock.
  Senders have no 60-second expiry. Require read-only AF_PACKET evidence at
  the LAN output that BOTH protocols emitted a frame timestamped after the
  barrier; sendall success or a silent/dead sender alone is insufficient.
  No drain/grace period hides post-barrier frames; kernel TCP ACKs are allowed.

The four executable cases are marked passed ONLY if the actual-client run
completes their assertions. Others keep explicit blocking prerequisite reasons;
no skips/xfails or fabricated pass. Unknown/malformed/failure packet responses
must fail, including helper timeout on a negative probe.

Review and first actual-client attempt
--------------------------------------
The first extended real-client run stopped with lab_policy_readback_mismatch.
The pinned controller's toPolicyResponse caches source groups across rules but
continues without appending a cached source to subsequent rules (policies_handler.go
source loop). This is an upstream API formatter defect, not proof of native
forwarding failure. Do NOT infer/restore missing fields or relax readback. The
fixture now uses independent one-rule TCP, UDP and ICMP policies, with protected
lab IDs, verified create/update/delete and ONE mutation per control operation.
All AFFECTED primary/backup routers must acknowledge a new map between operations. No controller patch.

Review P1s also added mandatory crossed-protocol negative probes and post-barrier
LAN wire proof, so dead/finished senders cannot produce a false revocation pass.
Review P2 caps ping lookup+exec with one remaining deadline (not 600 seconds).
The first run's 17 passes / 21 failed-or-blocked entries do NOT constitute
completion of the four new cases. The final-head rerun is authoritative.

The next real run reached a fixture publication timeout before the independent-
source case completed: it incorrectly waited for A's unchanged native policy
after editing only B. Unaffected routers need not republish. Barriers now track
only the edited customer's PRIMARY AND BACKUP, still one mutation at a time.
The aborted run (16 passing entries, 22 failed/blocked) is not new case proof.

The f0c4991 actual run proved A, E and F (RELATED-ICMP, protocol/port restrictions,
independent customer sources). H correctly refused to pass with
lab_passive_sender_unproven: absence of client replies did not prove that both
senders emitted after the barrier. This is incomplete test evidence, not an
observed unauthorized reply. The subsequent fixture pauses application sends
BEFORE withdrawal, confirms TCP SIOCOUTQ=0 and both pause markers, retains the
same sockets, then resumes SERVER-ONLY writes AFTER the local-publication
barrier. Wire timestamps and client denial are still mandatory. There are no
new client application requests or permission/conntrack changes in this pause.
This specifically tests established-socket reply revocation, not uninterrupted
stream throughput during controller-to-kernel propagation. That stronger
concurrent/reset acceptance remains separately BLOCKED. No grace-period or
sender-silence pass is introduced. Only boolean per-protocol missing-proof
flags are exported if emission is still unproven.
