Confirmed defects and corrections
1. build-iso.sh used invalid xorriso syntax: -append_partition all revoke -.
   A real xorriso run failed before producing a usable image. Removed the
   invalid operation; preserve input boot structures with boot_image replay.
   Missing build tools now produce a specific error. Local independently
   verified SHA512 input does not unnecessarily require gpgv; remote downloads
   still require the signature verifier and trusted Debian CD keyring.
2. The beta bundle manifest omitted common/binat_acl.py although the core
   installs/runs it. Manifest-built ISO/Pi bundles therefore lost the NetBird
   ACL correction that a full checkout contained. Added the dependency and
   bundle manifest itself; regressions require every common Python module.
3. ISO firstboot and deferred Pi preparation did not collect/store a missing
   setup key. The core could ask again after interruption; deferred deployment
   cannot answer an interactive prompt. Collect it once BEFORE the core,
   only when read-only admission identifies no existing active identity.
   Preserve all credentials in root-only JSON on errors. Existing connected
   profiles require no setup key. No automatic reconnect/re-enrollment.
4. Repeating Pi preparation without --config ignored its saved pi.json and
   asked for tokens again. Reuse the protected file through the same admission
   and data-only parser; retain the original office fingerprint.
5. Pi staging copied entire checkout directories, including possible untracked
   customer files. Stage only the explicit bundle manifest. Validate all paths
   before copying; reject traversal, duplicates, source/destination symlinks.
   Existing customer files outside the source manifest remain unchanged.
6. Firstboot's RemainAfterExit held tty1 in conflict with getty after success.
   The oneshot now becomes inactive and asynchronously restores getty on exit.
   The protected DONE condition prevents another enrollment. Dangling input
   symlinks are rejected instead of being silently replaced.

7. Minimal Debian 13 lacked sysctl: the core used it without installing procps.
   Add the explicit dependency. QEMU executes real forwarding/packet checks
   after installing this package in the otherwise minimal guest.

8. The VM default entrypoint delegated interactive input directly to the core,
   which could ask for credentials again after failure. Read-only admission
   now precedes protected vm.json collection/reuse. Explicit --config updates
   that same protected input; direct legacy CLI options remain supported.

Reproduce the isolated lab
- Build tools: docker build -f tests/Dockerfile.platform-lab \
  -t openmain-platform-lab:debian13 .
- Create a NEW empty LAB directory. Preparation needs only Debian package
  mirrors and verifies the Debian archive. No router APIs or production tokens:
  docker run --rm -v "$LAB:/lab" openmain-platform-lab:debian13 debootstrap \
    --variant=minbase \
    --include=systemd-sysv,kmod,procps,python3,jq,nftables,iproute2,ifupdown,curl,gnupg,shellcheck,ca-certificates \
    trixie /lab/amd64 http://deb.debian.org/debian
  docker run --rm -v "$LAB:/lab" openmain-platform-lab:debian13 debootstrap \
    --foreign --arch=arm64 --variant=minbase --include=python3,jq \
    trixie /lab/arm64 http://deb.debian.org/debian
- Execute with network disabled, read-only source, no published ports:
  docker run --rm --network none -e OPENMAIN_ISOLATED_TEST=1 \
    -v "$LAB:/lab" -v "$PWD:/src:ro" openmain-platform-lab:debian13 \
    python3 tests/qemu_platforms.py
  docker run --rm --network none -e OPENMAIN_ISOLATED_TEST=1 \
    -v "$LAB:/lab" -v "$PWD:/src:ro" openmain-platform-lab:debian13 \
    python3 tests/arm64_platforms.py
  Use a NEW --work /lab/<name> on a repeated QEMU run; existing disks are
  never overwritten. Lab logs/images remain local; never commit runtime files.
- router-security-ci.yml automates both lab levels alongside existing offline
  and real-kernel tests. QEMU lab requires no privileged Docker/host networking.
